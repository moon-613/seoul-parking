### ② 주차장 — `raw/parking_standard.csv` + `raw/parking_seoul.csv`

**주차장 데이터를 2개 쓰는 이유**

주차장 데이터는 각각 **담고 있는 주차장이 다릅니다.** 어느 하나만 쓰면 특정 동네가 통째로 "주차장 0면"이 됩니다.

- **표준데이터만 쓰면** → 성수동·왕십리 같은 곳이 0면으로 나옵니다. 실제로 주차장이 없는 게 아니라, 그 자치구가 이 데이터에 등록을 안 한 것입니다.
- **서울시 API만 쓰면** → 거주자우선주차구획(주민 전용)이 섞여 들어옵니다. 홍대(서교동)가 6면으로 잡히는데, 그게 전부 1면짜리 주민 전용 자리였습니다.

그래서 **표준데이터를 기본으로 쓰되, 표준데이터에 0면으로 나오는 동네만 서울시 API로 채웁니다.**
이렇게 하면 겹치는 동네가 없으므로 **같은 주차장을 두 번 세는 일이 생기지 않습니다.**

| | 주(主) 데이터 | 보충 데이터 |
|---|---|---|
| **이름** | 전국주차장정보 표준데이터 | 서울시 공영주차장 정보 |
| **출처** | 공공데이터포털 · [15012896](https://www.data.go.kr/data/15012896/standard.do) | 서울 열린데이터광장 `GetParkInfo` |
| **수집** | `tn_pubr_prkplce_info_api` → 서울 필터 | OpenAPI |
| **규모** | 856개소 / 73,796면 | 2,189개소 / 61,035면 |
| **특징** | **거주지우선주차 제외** (방문객 분석에 적합) | 거주자우선 포함 |

**병합 규칙**: 표준데이터를 기본으로, **표준데이터에 0면인 동에만** 서울시 API로 보충
→ 겹치는 동이 없어 **이중 계산 불가능**

| 출처 | 동수 | 결과 |
|---|---|---|
| `standard` | 315개 | |
| `seoul_api` | 43개 | 성수1가2동(329면)·왕십리도선동(260면) 등 복구 |
| `none` | **66개** | 양쪽 모두 0면 |
| **합계** | **358개 / 78,267면** | |

**주요 컬럼 (표준데이터)**

| 컬럼 | 의미 |
|---|---|
| `prkplceNm` / `lnmadr` / `rdnmadr` | 주차장명 / 지번주소 / 도로명주소 |
| **`prkcmprt`** | **주차구획수 (= 공급)** |
| `prkplceSe` / `prkplceType` | 공영·민영 / 노상·노외·부설 |
| `basicCharge` / `basicTime` | 기본요금 / 기본시간(분) |

### 💡 핵심: 시간에 따라 변하는 건 생활인구뿐

주차·상권은 정적입니다. 그래서 **`slots_per_1k`처럼 생활인구를 분모로 쓰는 변수만** 요일·시간대에 반응합니다.

**예시 — 사직동**

| 요일 | 시간대 | 생활인구 | 공영주차면 | 1,000명당 |
|---|---|---|---|---|
| 금 | 점심 | 43,131 | 1,306 | 30.3 |
| 금 | 저녁밤 | 21,927 | 1,306 | **59.6** |

주차면은 같은데 사람이 절반이라 **체감 여유는 2배**입니다.

**제외 효과 — 요일별 변동계수(%)**

| 요일 | 포함 | **제외** |
|---|---|---|
| 수 | 2.01 | **0.19** |
| 금 | 2.97 | **0.38** |
| 나머지 | 변화 없음 | |

수·금 평균의 흔들림이 **10배 가까이 줄었습니다.**

> 현충일(6/6)은 토요일이라 이미 주말이므로 그대로 뒀습니다.
> 제헌절 연휴 주말(7/18~19)은 평소 주말보다 낮지만, 실제 주말이므로 포함했습니다.

포함해서 보려면: `build_panel.py --include-holidays`

## 5. 반드시 알아야 할 두 가지 처리

멘토링에서 "어떻게 붙였냐"고 물으면 이 두 가지입니다.

### ① 행정동코드 크로스워크 — 코드 체계가 서로 달랐음

> **한 줄 요약**
> 같은 사직동인데 데이터마다 코드가 달라서(`11110530` vs `11010530`),
> **양쪽 코드를 모두 가진 '전국 행정동 코드정보' 파일을 중간 다리로 놓고 행정동 이름으로 이어 붙였습니다.**

같은 사직동인데 데이터마다 코드가 다릅니다:

| 데이터 | 사직동 코드 |
|---|---|
| 생활인구 · 상권분석 | `11110530` (행정안전부 체계) |
| SGIS 경계 · 지오코딩 | `11010530` (SGIS 체계) |

그냥 조인하면 **424개 중 32개(7.5%)만** 맞습니다.

**해결**: '전국 행정동 코드정보'가 다리 역할
```
생활인구 코드 → ADMI_CD → FULL_NM → SGIS adm_nm → 경계
              (같은 체계)      (같은 형식)
```
→ **조인 성공률 100%** (인구 손실 0명)

처리한 예외: 가운뎃점 표기(`상계3.4동`↔`상계3·4동`) / 구버전 코드 7개 / 동 분할 1:2(상일동→상일1·2동) / 월별 누락

### ② 주차장 지오코딩 — 주차장에 행정동 정보가 없음

주차장 데이터에는 **주소만 있고 행정동이 없습니다.** 좌표도 결측이 있고요(표준 5.7%, 서울시 33.5%).

**해결**: SGIS 지오코딩 API가 좌표뿐 아니라 **행정동코드를 직접 반환**
```
"성동구 마장동 463-2" → adm_cd=11040540, adm_nm=마장동
```
→ 공간조인 없이 배정 완료, **배정률 100%**, 경계코드와 100% 일치

| **생활인구는 대리변수** | 통신 기반 추계치라 **차량 이용자 구분 불가** |
| **상권은 분기 고정** | 20261 단일 분기. 생활인구(일 단위)와 시간 해상도가 다름 |
