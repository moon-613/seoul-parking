실제 수집된 파일과 그 내용. 최종 확인 2026-08-10.

```
data/
├── raw/                     API로 받은 원본 (가공 전)
│   ├── living_population/   생활인구 56일치
│   └── parking_seoul.csv    공영주차장
├── external/                외부에서 받은 참조 데이터
│   ├── dong_boundary.geojson  행정동 경계
│   └── commercial/            상권분석 CSV (⬜ 미다운로드)
├── interim/                 중간 가공물 (아직 없음)
└── processed/               분석용 최종 테이블 (아직 없음)
```

## 4. 행정동코드 크로스워크 ✅ 해결됨

생활인구와 SGIS 경계는 코드 체계가 **다릅니다.**

| 출처 | 사직동 코드 |
|---|---|
| 생활인구 `ADSTRD_CODE_SE` | `11110530` (행정안전부 체계) |
| SGIS 경계 `adm_cd` | `11010530` (SGIS 자체 체계) |

직접 조인하면 424개 중 32개만 맞습니다.

**해결**: 서울 열린데이터광장의 **'전국 행정동 코드정보'** 가 다리 역할을 합니다.

```
생활인구 코드 → ADMI_CD → FULL_NM → SGIS adm_nm → 경계
```

**`external/adm_code/SEOUL_ADMI/ADMI_*.csv`** (43개월분)

| 컬럼 | 의미 |
|---|---|
| `ADMI_CD` | 행정동코드 — **생활인구와 같은 체계** |
| `FULL_NM` | 풀네임 — **SGIS `adm_nm`과 같은 형식** |
| `SIDO_NM` / `SGG_NM` / `ADMI_NM` | 시도 / 자치구 / 동명 |

**`external/dong_crosswalk.csv`** — 위 과정으로 생성한 최종 매핑표 (426행)

| 컬럼 | 의미 |
|---|---|
| `adm_cd` | SGIS 경계코드 |
| `admi_cd` | 생활인구 코드 |
| `adm_nm` / `sgg_nm` / `admi_nm` | 풀네임 / 자치구 / 동명 |

### 처리한 예외 3가지

| 문제 | 예시 | 처리 |
|---|---|---|
| 가운뎃점 표기 차이 | 매핑표 `상계3.4동` vs SGIS `상계3·4동` | `normalize_dong_name()` 정규화 |
| 구버전 코드 | 강북구 번1동: 생활인구 `11305590` vs 매핑표 `11305595` | 자치구 내 정렬 순서로 1:1 매칭 (7개) |
| 동 분할 (1:2) | 생활인구 `11740520`(구 상일동) = 경계 상일1동 + 상일2동 | `SPLIT_DONGS`로 명시, 경계를 dissolve |

**최종 결과: 생활인구 100% 조인, 인구 손실 0명**

> 통폐합으로 특정 월에만 존재하는 코드(용신동, 일원2동)가 있어
> **43개월 파일을 전부 병합**해 조회합니다.

생성 명령:
```powershell
.\.venv\Scripts\python.exe -m src.preprocess.dong_code
```
