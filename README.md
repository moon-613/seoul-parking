# 생활인구·거주형태 기반 서울 행정동별 공영주차 수급 진단

🔗 **대시보드 바로 열기 — https://seoul-parking.streamlit.app/** (설치 불필요)

**두 사람에게 서로 다른 답을 주는 하나의 분석입니다.**

| 사용자 | 묻는 것 | 받는 것 |
|---|---|---|
| 🎯 **나들이객** | 어느 동네에 언제 가면 주차가 덜 막힐까 | 추천 동네 23개 · 동네별 최적 시점 |
| 🏗️ **자치구 주차 정책 담당** | 공영주차장을 어디에 지어야 하나 | 확충 후보 52개 · **확충 불필요 13개** |

기존 주차 서비스(모두의주차장·서울주차정보)는 **목적지가 이미 정해진** 사람에게 주변 빈자리를 찾아줍니다. 이 프로젝트는 그 **이전 단계**와, 애초에 주차장을 어디에 놓을지를 다룹니다.

**분석 단위: 행정동 × 요일 × 시간대 = 17,808행 × 31열** (424 × 7 × 6)

---

## 가장 중요한 발견

> **서울 공영주차장 배치는 어떤 수요 지표로도 설명되지 않습니다.**

| 수요 지표 | R² | 뜻 |
|---|---|---|
| 생활인구 (유동수요) | **0.068** | 사람이 얼마나 오는지와 거의 무관 |
| 비아파트 가구 (정주수요) | **0.004** | 실거주 수요와도 무관 |

논현2동은 4.4만 명에 **13면**, 도봉1동은 1.75만 명에 **1,413면**입니다.
가설이 기각된 것 자체가 결과이며, **배치가 수요 기반이 아니므로 재설정할 근거**가 됩니다.

⚠️ **다만 이 낮은 설명력 때문에 회귀 잔차를 "수요 대비 부족"으로 읽으면 안 됩니다.**
회귀선이 평평하면 잔차는 사실상 주차면 수 그 자체가 됩니다(순위상관 0.997).
그래서 확충 우선순위는 회귀를 거치지 않은 **직접 지표**로 제시합니다.

  ✅        ✅         ✅          ✅         ⬜          ✅           ⬜

### ① 기획 ✅

- **분석 단위**: 행정동 × 요일 × **시간대 6구간** — 아침(6-10)·오전(10-12)·점심(12-15)·오후(15-18)·저녁(18-21)·밤(21-24)
- **00~06시(심야)는 제외**합니다
- **아침(6-10)은 조회는 되지만 '언제 가면 좋은가' 추천에서는 뺍니다.** 이 시간대는
  주차가 비는 게 아니라 사람이 없어서 비는 것이라, 나들이 시점으로 내밀 수 없습니다
  (제외 대상은 `config/config.yaml`의 `recommend_exclude` 한 곳에서 관리)
- 기획서: `submission/01_보고서/`

**방향을 네 번 바꿨습니다** — 왜 바꿨는지가 곧 분석 과정입니다

| 시점 | 변경 | 이유 |
|---|---|---|
| 수집 중 | 실시간 주차 → **구조적 과부족** | `CUR_PARKING` 컬럼 폐지 확인 |
| 분석 중 | 주차 공급 → **공영주차** | 민영 미공개로 측정 대상을 정직하게 한정 |
| Day 2 오전 | 부사용자 제거 → 사용자 단일화 | 확충 논의까지 번져 초점이 흐려짐 |
| Day 2 오후 | **부사용자 복원 + 거주형태 도입** | 단일화하니 분석이 아니라 서비스 기획이 됐고, 핵심 기능(관심 장소 매칭)은 네이버·카카오 API 미제공으로 구현 불가 |

### ③ 전처리 ✅

이 프로젝트에서 **가장 오래 걸린 단계**입니다.

| 모듈 | 한 일 | 결과 |
|---|---|---|
| `dong_code.py` | 서로 다른 행정동코드 체계 연결 | 조인율 **7.5% → 100%** |
| `geocode_parking.py` | 주소 → 행정동 배정 | 배정률 **100%** |
| `load_census.py` | 거처종류별 가구 결합 | **424/424 (100%)** |
| `build_panel.py` | 집계·병합·파생, 공휴일 제외 | **17,808행 × 31열** |
| `validate.py` | 중복·논리·결측·이상치 검증 | 전 항목 통과 |

```bash
python -m src.preprocess.dong_code
python -m src.preprocess.geocode_parking --source standard
python -m src.preprocess.geocode_parking --source seoul
python -m src.preprocess.build_panel --quarter 20261
python -m src.preprocess.validate
```

**까다로웠던 지점**

- 생활인구(행안부 코드) ↔ SGIS 경계(자체 코드) → 코드정보 파일을 다리로 연결
- 주차장에 행정동 정보가 없어 SGIS 지오코딩으로 배정 (좌표 결측 5.7~33.5%)
- 총조사에 **자치구 컬럼이 없어** 동명이인(신사동)을 파일 순서로 구분, 통합 동 2건 합산
- 비아파트 가구는 **합산이 아니라 차감**(일반가구−아파트) — 소분류가 비공개(X)라 더하면 결측이 번짐
- **평일에 낀 공휴일 2일 제외** (지방선거 6/3, 제헌절 7/17) → 변동계수 수 2.01%→0.19%
- 이상치는 **제거하지 않음** — 서교동 117,158명은 오류가 아니라 실제 번화가

### ④ 분석 ✅ — 가설 6개 전부 검증

```bash
python -m src.analysis.daily_trend       # 일별 추세·공휴일 검증
python -m src.analysis.explore           # 상관·자치구 분포 (가설 1·3)
python -m src.analysis.residual          # 회귀 잔차          ← recommend의 입력
python -m src.analysis.recommend         # 추천/회피 동네 (가설 4)
python -m src.analysis.cluster           # 동네 유형 (가설 2)
python -m src.analysis.timeslot_effect   # 시간대 효과 (가설 5)
python -m src.analysis.real_demand       # 실수요 진단 (가설 6)
python -m src.analysis.suitability       # 나들이 적합도 지수
python -m src.analysis.district          # 자치구 요약
python -m src.analysis.maps              # 공간 분포 지도
```

> **실행 순서 주의** `residual` → `recommend`, `real_demand`·`suitability` → `district`·`maps`
> `daily_trend`만 `data/raw`(157MB)가 필요하고 나머지는 `panel.csv`만 있으면 됩니다.

| 가설 | 판정 | 핵심 수치 |
|---|---|---|
| 1. 유동인구↑ → 1인당 주차면↓ | 약한 지지 | r = −0.14 |
| 2. 유형별 시간대 패턴 차이 | **지지** | 상권형 여유 **일·밤(134)** / 주거형 여유 화·점심(107) — 정반대 |
| 3. 20~30대·음식점 ↔ 주차면 | **기각** | r = −0.02 |
| 4. 매력도+주차 여유 예외 지역 | **지지** | 추천 23개 · 혼잡 주의 21개 |
| 5. 시간대 조정 효과 | **지지** | 프리드먼 p=1.3e-227 · 개선율 중앙값 **+34.5%** · 85.2%가 +20% 이상 |
| 6. 아파트가 만드는 판정 오탐 | **지지** | 확충 불필요 9개 중 **4개**가 생활인구 기준으론 '공급부족' |

**가설 2** — 실루엣 기준 유형은 **2개**입니다(어떤 피처 조합에서도 k=2). 기획서가 예상한 3유형은 데이터가 지지하지 않습니다.

**가설 6** — 상계9동은 비아파트 **4가구**인데 생활인구 기준으로는 확충 대상으로 지목됐습니다. 아파트가 부설주차장으로 실수요를 흡수한 곳입니다.

## 알려진 한계

| 한계 | 내용 |
|---|---|
| **잔차 ≠ 수요 대비 부족** | 설명력이 낮아 회귀선이 평평하고, 잔차 순위가 주차면수 순위와 0.997 일치. 확충 순위는 직접 지표로 제시 |
| 민영주차장 없음 | 서울 25개 구 중 2개 구 45건만 공개 → 측정 대상은 **공영주차** |
| 0면 행정동 66개 | 실제 0이나 민영 미개방 영향 혼재 → `has_parking`으로 분리 |
| 총조사 시점 불일치 | 거처종류별 가구는 5년 주기(최신 2025) vs 생활인구 2026 |
| 아파트 = 주차 해결 아님 | 노후 아파트는 세대당 주차대수가 기준 미달 → 비아파트 가구는 **대리변수** |
| 실시간 불가 | `CUR_PARKING` 폐지 → 8주 평균 패턴 |
| 생활인구는 대리변수 | 통신 추계치라 **차량 이용자 구분 불가** |
| 테스트 없음 | 기존 테스트는 대상 모듈 삭제로 제거, 신규 미작성 |
