# 대시보드 스크린샷

Streamlit 대시보드(`dashboard/app.py`) 5개 페이지 전체 화면 캡처. 발표자료·보고서 삽입용.

- 캡처 일시: **2026-08-12**
- 해상도: 폭 1,600 CSS px를 **2배 배율**로 캡처 → 실제 파일은 폭 3,200px (인쇄·슬라이드 확대에도 글자가 깨지지 않습니다)
- 페이지 전체를 한 장에 담았습니다(스크롤 잘림 없음)
- 사이드바 조회 조건은 전 페이지 공통 **토요일 · 오후 15-18시 · 자치구 전체**
- 화면 정리를 위해 Streamlit 개발용 UI(Deploy 버튼·햄버거 메뉴·푸터)는 숨겼습니다

| 파일 | 크기 | 페이지 | 사용자 | 담은 내용 |
|---|---|---|---|---|
| `01_현황.png` | 3200 × 5478 | 🅿️ 현황 | 나들이객 | KPI 4종 · 시간대별 생활인구 곡선 · 자치구 여유도 · 동네 순위 |

| `03_동네추천.png` | 3200 × 5534 | 🎯 동네 추천 | 나들이객 | 매력도 × 주차여유 사분면 · 적합도 랭킹 · 최적 방문 시간대 |

## 발표에서 어느 장면을 쓸까

- **`05_확충우선순위.png`의 ③ 생활인구만 보면 생기는 판정 오류** — 가장 의미 있는 결과입니다.
  상계9동은 비아파트가 4가구뿐인데 생활인구 기준으로는 '공급부족'으로 잡혔습니다.
  예산이 잘못 갈 뻔한 지점을 대시보드가 짚어 줍니다.
- **`02_지도.png`** — 순위표만으로는 안 보이는 "확충 후보가 관악·종로·성북에 몰린다"가 드러납니다.
- **`03_동네추천.png`** — 주 사용자(나들이객) 시나리오를 한 장으로 보여 줍니다.

## 재현 방법

```bash
streamlit run dashboard/app.py    # → http://localhost:8501
```

캡처는 설치된 Chrome을 Playwright로 구동해 자동으로 찍었습니다. 수동으로 다시 찍는다면
브라우저 폭을 1,600px로 맞추고 페이지 전체 캡처 기능을 쓰면 같은 구도가 나옵니다.

> ⚠️ Streamlit은 화면 밖 요소를 늦게 그립니다. 캡처 전에 **페이지를 끝까지 한 번 스크롤**해
> 모든 차트가 그려진 것을 확인해야 빈 회색 상자가 남지 않습니다.
