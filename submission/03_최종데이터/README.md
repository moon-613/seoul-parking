# 최종 데이터

서울시 생활인구 기반 행정동별 주차수급 불균형 진단 및 취약지역 도출 — 분석 산출 테이블 8종

- 인코딩: **UTF-8 (BOM 포함)** — Excel에서 바로 열면 한글이 깨지지 않습니다
- 공간 단위: **행정동 424개** (서울시 전체, 생활인구 미제공 1개 동 제외)
- 기준 기간: **2026-06-02 ~ 2026-07-27 (56일)**, 평일에 낀 공휴일 2일 제외
- 원본 데이터는 용량 문제로 포함하지 않았습니다. 재현은 저장소의 `src/collect` → `src/preprocess` → `src/analysis` 순으로 실행하면 됩니다

### 행 수가 424가 아닌 이유

동마다 분모가 달라 계산이 성립하는 범위가 다릅니다. **결측이 아니라 정의상 제외**입니다.

| 행 수 | 제외 대상 |
|---|---|
| 424 | 전체 (`panel`) |
| 423 | 상권 매력도 결측 1개 동 (`recommend`) |
| 422 | 인구주택총조사 미매칭 2개 동 (`real_demand`) |
| 358 | 공영주차 **0면 66개 동** — 천명당 주차면·잔차 계산 불가 (`residual`, `timeslot`) |
| 357 | 위 + 매력도 결측 1개 (`suitability`) |
| 351 | 위 + 직장인구 미제공으로 주거지수 산출 불가 (`cluster`) |

> `dong_recommend.csv`만 0면 66개 동을 **포함**합니다. 이용자에게는 "공영주차가 아예 없는 동네"가
> 가장 먼저 알아야 할 정보라 `등급 = 공영주차 없음`으로 별도 표시했습니다.

## 1. `panel.csv` — 기본 패널 (14,840 × 31)

한 행 = **한 행정동의 한 시점**(요일 × 시간대). 나머지 7개 파일이 전부 이 테이블에서 파생됩니다.

| 컬럼 | 설명 |
|---|---|
| `adm_cd` / `admi_cd` | SGIS 코드 / 행정안전부 행정동코드 |
| `sgg_nm` / `admi_nm` | 자치구명 / 행정동명 |
| `weekday` | 월·화·수·목·금·토·일 |
| `is_weekend` | 주말 여부 |
| `timeslot` | 오전(10-12) · 점심(12-14) · 오후(14-18) · 저녁(18-21) · 밤(21-24) |
| `living_pop` | **생활인구** — 그 시각 그 동에 있는 모든 사람 (유동수요) |
| `young_pop` / `young_ratio` | 20~30대 인구 / 비중 |
| `parking_slots` / `parking_lots` | 공영주차면수 / 주차장 개소 |
| `avg_fee_per_hour` / `source` | 시간당 평균요금 / 출처(표준데이터 · 서울시API 보충) |
| `store_food` / `store_cafe` / `facility_cnt` | 음식점 / 카페 / 집객시설 수 |
| `resident_pop` / `worker_pop` | 상주인구 / 직장인구 |
| `households` / `apartment` | 일반가구 / 아파트 가구 |
| **`non_apt_households`** | **비아파트 가구** = 일반가구 − 아파트. 부설주차장이 없어 공영주차에 의존 (정주수요) |
| `apt_ratio` | 아파트 거주 비율 |
| `detached` / `rowhouse` / `multiplex` / `non_house` | 단독 / 연립 / 다세대 / 주택이외 거처 |
| **`slots_per_1k`** | **천명당 주차면** = 주차면 ÷ 생활인구 × 1,000. **시간에 따라 변하는 유일한 지표** |
| `has_parking` | 공영주차 보유 여부 |
| `slots_per_100_nonapt` | 실수요 100가구당 주차면 |

> ⚠️ 주차면수는 시간에 따라 변하지 않습니다. `slots_per_1k`가 흔들리는 건 **분모인 생활인구**
> 때문입니다. "주차장이 늘어난다"가 아니라 "같은 주차장을 두고 경쟁할 사람이 줄어든다"입니다.

## 2. `dong_residual.csv` — 회귀 잔차 (358 × 12)

"사람이 이만큼 오는 동네면 공영주차가 대략 이 정도는 있겠다"는 기준선을 로그-로그 회귀로 긋고,
실제가 그 선보다 얼마나 위/아래인지를 봅니다.

| 컬럼 | 설명 |
|---|---|
| `expected_slots` | 회귀 기준선이 예측한 주차면수 |
| `supply_ratio` | 실제 ÷ 기대 |
| `residual` / `z_residual` | 잔차 / 표준화 잔차 |
| `grade` | **공급부족 56 · 보통 248 · 공급여유 54** (z ≤ −1 / −1~+1 / ≥ +1) |

R² = 0.074. **설명력이 낮다는 것 자체가 발견**입니다 — 현재 배치가 생활인구·상권 규모로 거의
설명되지 않는다는 뜻입니다.

## 4. `dong_cluster.csv` — 동네 유형 (351 × 17)

| 컬럼 | 설명 |
|---|---|
| `유형` | **상권형 112 · 주거형 239** — 실루엣 계수 기준 k=2가 최적 |
| `home_index` | 주거지수 = 상주 ÷ (상주 + 직장). 1에 가까우면 주거지 |
| `food_per_1k` / `fac_per_1k` | 천명당 음식점 / 집객시설 |
| `PC1` / `PC2` | 주성분 좌표 |

> 군집 번호(0, 1)는 실행마다 바뀌므로 **특성으로 이름을 고정**했습니다. 기획서가 예상한 3유형은
> 데이터가 지지하지 않습니다.

## 5. `dong_timeslot.csv` — 시간대 조정 효과 (358 × 10)

| 컬럼 | 설명 |
|---|---|
| `최적요일` / `최적시간대` / `최적값` | 천명당 주차면이 가장 여유로운 시점 |
| `최악요일` / `최악시간대` / `최악값` | 가장 빠듯한 시점 |
| `개선율` | (최적 − 최악) ÷ 최악 × 100(%) |

프리드먼 검정 p = 1.3e-227, 개선율 중앙값 **+34.5%**, +20% 이상 개선 305/358개(85.2%).

## 6. `dong_real_demand.csv` — 실수요 진단 (422 × 17)

수요 지표를 둘로 나눠 판정이 갈리는 지점을 봅니다.

| 컬럼 | 설명 |
|---|---|
| `확충필요성` | **검토대상 409 · 불필요 13** (비아파트 100가구 미만) |
| `구분` | 일치 398 · 확충 불필요 13 · 정주만 부족 6 · **유동만 부족(아파트 흡수형) 3** · **유동만 부족(방문객 수요형) 2** |
| `판정_유동` / `판정_정주` | 생활인구 기준 / 비아파트 가구 기준 등급 |
| `z_유동` / `z_정주` | 각 기준의 표준화 잔차 |

> **오탐 제거가 이 파일의 목적**입니다. 상계9동은 비아파트가 4가구뿐인데 생활인구 기준으로는
> '공급부족'으로 잡혔습니다. 비아파트 가구는 설명력 개선용이 아니라 오탐 제거용 지표입니다.

## 7. `dong_suitability.csv` — 나들이 적합도 (357 × 14)

| 컬럼 | 설명 |
|---|---|
| `나들이적합도` | 매력도 × 주차여유의 **기하평균** (0~100) |
| `매력도지수` / `_pct` | PC1 (52.1%) — 음식점·카페·집객시설 축 |
| `주차여유지수` / `_pct` | PC2 (39.2%) — 천명당 주차면·주차여유 축 |

가중치를 사람이 정하지 않았습니다. **PCA가 데이터에서 두 축을 스스로 분리**했고 두 축 합계
설명력은 91.3%입니다. 나들이는 약한 쪽이 병목이라 산술평균이 아닌 **기하평균**을 씁니다.

## 인용 시 주의

1. **잔차를 '수요 대비 부족'으로 읽으면 안 됩니다.** 잔차와 주차면수의 순위상관이 0.997이라
   회귀 보정이 사실상 없습니다. 확충 우선순위는 잔차가 아니라 `slots_per_100_nonapt`(직접 지표)로 냈습니다.
2. **공영주차만 다룹니다.** 민영주차장은 표준데이터 수집 범위가 지자체 관리 대상으로 한정되어
   서울 25개 구 중 2개 구 45건뿐이라 측정 대상에서 뺐습니다.
3. **비아파트 가구는 실수요의 상한이 아니라 대리변수**입니다. 1990년대 이전 아파트는 세대당
   주차대수가 0.3~0.7대로 지금 기준에 못 미칩니다.
